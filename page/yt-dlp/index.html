-- **CLI apps notes** Want to download videos to archive things cleanly? {keyword:yt-dlp} (formerly youtube-dl) [https://github.com/yt-dlp/yt-dlp](https://github.com/yt-dlp/yt-dlp) [https://github.com/yt-dlp/yt-dlp/archive/refs/heads/master.zip](https://github.com/yt-dlp/yt-dlp/archive/refs/heads/master.zip) -- "Hey, didn't this get taken down from GitHub at some point?" Yes, but after review they concluded there was no actual valid reason for it to be removed. They just took it down in response to legal notices or something while pending review, then it came back. "How do I download from GitHub? Where's the .exe file?" Under the green 'Code' button, choose Download in the drop-down (probably 'Download ZIP'). I also linked directly to this zip above, so visiting that url is all you do. There is no 'installation' after you unzip this folder -- once you have those files in a folder, that's it, you can use it. To interact with these files, you open your console (in Windows, hold the Windows logo key and press 'R' to open the run prompt, then enter 'cmd' -- or search for the 'Command Prompt' application in your Start Menu), and navigate to that directory using the 'cd' (change directory) command. If you placed the folder on your desktop, for example, the command to get to it would look like this: > cd C:\Users\Iris\Desktop\yt-dlp Then you type commands to interact with the software inside that console. This is called a command-line interface (CLI) application. Once you're in the repo you placed it in (e.g. C:\yt-dlp or C:\Users\YourName\yt-dlp), you begin your prompt with "yt-dlp" (which invokes the "yt-dlp.cmd" file in that directory). Instead of navigating to the directory, you can reference it from anywhere by entering the path from root, i.e. saying "C:\yt-dlp\yt-dlp ..." each time. Or, you can add the relevant directory to your system's environment path variables, allowing you to invoke it from anywhere. In Windows 10, you do so with these steps: * Run 'SystemPropertiesAdvanced.exe' and go to the 'Advanced' tab (if you search 'environment variables' in your Start Menu, there may be a link called 'Edit the system environment variables' that takes you to right the Advanced tab of this menu) * Click the 'Environment Variables' button * In the 'System Variables' section of the window this opens, find the 'Path' variable and double-click the associated 'Value' to open a window wherein you can add entries to that value. * Add an entry for your yt-dlp directory (add ffmpeg while you're here). -- **Options and arguments** An {keyword:option} is the proper term for an inline function prefixed with one or two hyphens depending on whether it's a verbose or short option name (for example, -f and --format, which both do the same thing). This is typically followed by an input value that you send to the option, which is called an {keyword:argument}. If you enter `yt-dlp -f "230+180" "https://youtu.be/..."` into your console, that whole line is called a command (hence the Windows name 'Command Prompt'). The `yt-dlp` at the start is the command's executable, referencing a file (something called 'yt-dlp' in the current directory); along the way, there's an -f option, which is accepting the string "230+180" as its argument; and then the YouTube link is the main command argument (logically it must be so because it's the only value that isn't prefixed with a dash, to indicate it's an option, nor comes immediately after an option that was expecting an argument). An option which doesn't take an argument is called a {keyword:flag} (e.g. if you add `-q` or `--quiet` to your command, it will execute quietly, i.e. with no output logs or progress indicator), and sometimes people imprecisely refer to all options as flags. The options you include in your command may occur in any order, so long as options and their accompanying arguments are still next to one another -- e.g. `yt-dlp -f "252+180" -o "C:\Users\..." "https://youtu.be/..." -q` is the same as `yt-dlp -q "https://youtu.be/..." -f "252+180" -o "C:\Users\..."` Common options: -o -- Output, tells yt-dlp where to put the file it downloads (defaults to bin) -- e.g. -o "C:\Users\Iris\Desktop\%(title)s.%(ext)s" to save to desktop (you can type in a specific file name if you want) -F -- See available file formats; renders a bit list of all available marked by an ID number on the left side. To specify what version you want from that list, use -f followed by your choices by their ID number in a string, e.g. yt-dlp -f "232+251" "video_url_here" -f or --format -- This tells yt-dlp to download with a given formatting option as opposed to default formatting (if no format option is given, the default behaviour is equivalent to `-f "bv+ba/b"` Arguments often used in the format string option: bv -- best video (only video) bv* -- best video (with audio, or only audio) ba -- best audio b -- best combined video+audio file --merge-output-format -- Forces the output to be a certain container, useful to say mp4 since it's not guaranteed to be mp4 otherwise -v or --verbose -- Gives additional detail, can be useful if something fails and you want more info --force-keyframes-at-cuts -- Prevents keyframe padding in output file (see below) -ppa or --postprocessor-args -- To apply encoding commands to your output file after downloading (complicated) Operators: + -- Merge -- e.g. bv+ba means best video and best audio / -- Fallback -- e.g. bv*+ba/b means try to find best audio track + best video track, but if it can't find both, then look for the best combined file [] -- creates a filter -- e.g. `-f "b[height<=1080]"` prevents downloading video with height greater than 1080p * -- varies contextually, but often used to create ambiguity, wildcard, or loosen otherwise standard requirements See more: [https://github.com/yt-dlp/yt-dlp#general-options](https://github.com/yt-dlp/yt-dlp#general-options) [https://github.com/yt-dlp/yt-dlp#user-content-format-selection](https://github.com/yt-dlp/yt-dlp#user-content-format-selection) -- **Making cuts of specific parts of videos** (1) Directly download the part you want with the {keyword:--download-sections} option > yt-dlp --download-sections "*2:12-4:00" "https://youtu.be/..." The * is necessary here to indicate it's a timestamp as opposed to a chapter title, which is the default behaviour. This method is useful for simply grabbing specific short clips. (2) Download the whole video (just using `yt-dlp "https://youtu.be/..."` with whatever options you want), then also make separate cuts locally using ffmpeg. For example, if you have a large file and want to create a cut between 31:14 and 1:24:03: > ffmpeg -ss 31:14 -to 1:24:03 -i "PATH_TO_YOUR_LOCAL_FILE" -c copy -avoid_negative_ts make_zero "C:\Users\Iris\Desktop\example_output--cut.mp4" The time argument in these commands also accepts raw seconds, e.g. if you say 1874 instead of 31:14 and 5043 instead of 1:24:03. This may be useful to note if you have timestamps in the form of YouTube query strings (e.g. https://youtu.be/...&t=531) which measures time in total seconds. These methods both may result in your video having some extra seconds at the beginning or end. This is because the command is looking at the video keyframes and finding the nearest one that precedes your start time and the nearest one that comes after your endtime. For example, if you ask for 31:14 to 1:24:03, you might get an output of 31:12 to 1:24:06 (but you will always get at least the part you wanted). "What's a video keyframe?" A video file might be 30 fps, but to render 5 seconds of video, it doesn't actually save 150 full images. It saves one image, then saves 149 instructions on how to modify that image each frame, saving the difference between frames rather than whole pictures. That starting frame, which the others are modifying, is called a key frame, or keyframe, also called i-frames. The space between keyframes isn't constant (they're often between 2 and 10 seconds apart), and part of what your computer is doing when you render a new video is figuring out where it makes the most sense to put these frames across your video. You can examine the location of keyframes in a video file using the ffmpeg tool called ffprobe. If you've ever been watching a video and there's a glitch where everything becomes distorted (often green) but you can still see movement or make out the bounds of characters, this is because the starting keyframe for that chunk was corrupted or distorted, but the player is still applying the changes in the other frames to that faulty starting point. To avoid ending up with extra padding due to it snapping to the nearest keyframes, you can use the --force-keyframes-at-cuts flag in your command. This will cause yt-dlp to reencode the video and thus takes significantly longer, but gives you a precise start and end point. This can also often solve video/audio desync if you're making cuts from longer videos. -- **Command I often use** This is the exact command I use to archive a full video: > yt-dlp -f "bv*[height<=720][fps<=30][vcodec^=avc1]+ba[acodec!^=opus]/b[height<=720][vcodec^=avc1][fps<=30]" "DESIRED_VIDEO_URL_HERE" --merge-output-format mp4 -o "G:\archive\public-record\%(title)s.%(ext)s" Notes about this command: * The -o flag ensures the output is an mp4 container. This means the file extension of your chosen files (the 'EXT' column in the format table) is unimportant, but the codecs (how information is stored inside the box) still matters. At this point in time mp4 remains the best option for general compatibility. * A filter in the -f option argument (height<=720) gets the highest video resolution available not exceeding 720p (1280x720). That is generally sufficient. 1080p or 2160p (often called 4k) files will be at least multiple times larger for what is in many cases unnecessary pixel detail. If you want larger copies, remove the [height<=720] filter. * A filter in the -f option argument (vcodec^=avc1) forces a download of the avc1 video codec, better known as H.264. This is by far the most common and widely available used video codec in general, which I therefore prefer to maximize file compatibility. If you don't include this, yt-dlp will often download a video file using the AV1 codec, which has more efficient compression (lower file size) and is thus preferred by YouTube itself to reduce bandwidth. * A filter in the -f option argument (acodec!^=opus) prevents downloading audio using the opus codec. This is a high quality codec often served by YouTube while you're watching videos, but it doesn't have the best compatibility (not all software can read it and you can't post opus audio on Twitter, for example). * A filter in the -f option argument (fps<=30) gets the highest frame rate available not exceeding 30. Many modern YouTube uploads have 60-fps video files available, but I find the extra frames pointless for most videos being archived. A 60-fps file will typically be between 1.5x and 2x the file size of an equivalent 30-fps file. No matter what command you use, your file will be playable in VLC media player, but getting the right codec affects what other programs or websites you can drag your file onto and have it be compatible. If you ever have issues getting the right output for your purposes, you can always use -F and pick the exact files you want yourself. It might be intimidating for a second because a lot of information comes up at once but if you take a minute to parse what's shown it shouldn't be that hard to understand. If I want to make a cut of the full video after downloading it via the above I use the exact ffmpeg command already shown: > ffmpeg -ss 21:20 -to 28:30 -i "path_to_your_local_file" -c copy -avoid_negative_ts make_zero "C:\Users\Iris\Desktop\example_output--cut.mp4" However, I frequently skip all this and only download sections when I'm archiving interesting parts of very long videos by using the --download-sections option. The exact command would be just like the above but with that option added, like this: > yt-dlp --download-sections "*1:22:33-4:55:66" -f "bv*[height<=720][fps<=30][vcodec^=avc1]+ba[acodec!^=opus]/b[height<=720][fps<=30][vcodec^=avc1]" "DESIRED_VIDEO_URL_HERE" --merge-output-format mp4 -o "G:\archive\public-record\%(title)s.%(ext)s" --
