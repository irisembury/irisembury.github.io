Yes, but after review they concluded there was no actual valid reason for it to be removed. They just took it down in response to legal notices or something while pending review, then it came back. "How do I download from GitHub? Where's the .exe file?" Under the green 'Code' button, choose Download in the drop-down (probably 'Download ZIP'). I also linked directly to this zip above, so visiting that url is all you do. There is no 'installation' after you unzip this folder -- once you have those files in a folder, that's it, you can use it. To interact with these files, you open your console (in Windows, hold the Windows logo key and press 'R' or search for the 'Command Prompt' application in your Start Menu) and navigate to that directory using the 'cd' (change directory) command. If you put the folder on your desktop, the command to get to it would look like this: > cd C:\Users\Iris\Desktop\yt-dlp Then you type commands to interact with the software as a command-line interface (CLI) application. This means once you're in the repo you placed it in (e.g. C:\yt-dlp or C:\Users\YourName\yt-dlp), you begin your prompt with "yt-dlp" (which invokes the "yt-dlp.cmd" file in that directory). Instead of navigating to the directory, you can reference it from anywhere by entering the path from root, i.e. saying "C:\yt-dlp\yt-dlp ..." each time. Or, you can add the relevant directory to your system's environment path variables, allowing you to invoke it from anywhere. - Run 'SystemPropertiesAdvanced.exe' and go to the 'Advanced' tab (if you search 'environment variables' in your Start Menu, there may be a link called 'Edit the system environment variables' that takes you to right the Advanced tab of this menu) - Click the 'Environment Variables' button - In the 'System Variables' section of the window this opens, find the 'Path' variable and double-click the associated 'Value' to open a window wherein you can add entries to that value. - Add an entry for your yt-dlp directory (add ffmpeg while you're here). -- **Options and arguments** An {keyword:option} is the proper term for an inline function prefixed with one or two hyphens depending on whether it's a verbose or short option name (for example, -f or --format, both doing the same thing). This is typically followed by an input value that you send to the option, which is called an {keyword:argument}. An option which doesn't take an argument is called a {keyword:flag} (e.g. you just say -q or --quiet as part of your command and the command will execute quietly, i.e. with no progress indicator or output logs), and sometimes people imprecisely refer to all options as flags. The options in an invocation of the program can happen in any order so long as the accompanying argument comes right after. Common options: -o -- Output, tells yt-dlp where to put the file it downloads (defaults to bin) -- e.g. -o "C:\Users\Iris\Desktop\%(title)s.%(ext)s" to save to desktop (you can type in a specific file name if you want) -F -- See available file formats; renders a bit list of all available marked by an ID number on the left side. To specify what version you want from that list, use -f followed by your choices by their ID number in a string, e.g. yt-dlp -f "232+251" "video_url_here" -f or --format -- This tells yt-dlp to download with a given formatting option as opposed to default formatting (if no format option is given, the default behaviour is equivalent to `-f "bv+ba/b"` Arguments often used in the format string option: bv -- best video (only video) bv* -- best video (with audio, or only audio) ba -- best audio b -- best combined video+audio file --merge-output-format -- Forces the output to be a certain container, useful to say mp4 since it's not guaranteed to be mp4 otherwise -v or --verbose -- Gives additional detail, can be useful if something fails and you want more info Operators: + -- Merge -- e.g. bv+ba means best video and best audio / -- Fallback -- e.g. bv*+ba/b means try to find best audio track + best video track, but if it can't find both, then look for the best combined file [] -- creates a filter -- e.g. -f "bv*[height<=720]+ba/b[height<=720]" creates a quality ceiling (get the best version not exceeding 720p) * -- Often used to create ambiguity, wildcard, or loosen otherwise standard requirements See more: https://github.com/yt-dlp/yt-dlp#general-options https://github.com/yt-dlp/yt-dlp#user-content-format-selection -- **Downloading Parts** (1) Simple method (slow): --download-sections option > yt-dlp --download-sections "*2:12-4:00" "https://youtu.be/Q_ltXhrXb6s" The * is necessary here to indicate it's a timestamp as opposed to a chapter title, which is the default behaviour. This method can be useful for grabbing specific short clips, however for long selections (more than a few minutes) it will become very time-consuming because yt-dlp is requesting the necessary data chunks from YouTube and then reëncoding the entire video to give you precisely the time selection you ask for, no more or less. If you want to download approximately from 30:00 to 1:30:00 from a 4-hour video, it is significantly faster to download the whole video, splice it locally, and delete the excess rather than use --download-sections "*30:00-1:30:00" and wait for the encoding. (2) Faster method: download it and cut it with ffmpeg Download the whole video, then cast your desired start and end point into seconds. For example, 31:14 is 1874 seconds, and 1:24:03 is 5043 seconds. This command should find the nearest video keyframe that precedes your start time and the nearest keyframe that comes after your endtime, meaning it may include a few extra seconds at the start or end. However, the trade-off is that this happens very quickly. > ffmpeg -ss 3238.120 -to 6123.510 -i "path_to_your_local_file" -c copy -avoid_negative_ts make_zero "C:\Users\Iris\Desktop\example_output--cut.mp4" "What's a video keyframe?" A video file might be 60 fps, but to render 5 seconds of video, it doesn't actually save 300 full images. It saves one image, then saves 299 instructions on how to modify that image, saving the difference between frames rather than whole frames. That first frame, which the others are modifying, is called a key frame, or keyframe, also called i-frames. They're not always 5 seconds apart; that is just an example value. Part of rendering a video is deciding where to put these key frames depending on how different each frame is from the next. It's common for them to be 4 to 6 seconds apart. You can examine where the keyframes are in a video file using the ffmpeg tool called ffprobe. If you've ever been watching a video and there's a glitch where everything becomes distorted (often green) but you can still see the movement and make out the bounds of characters, this is because the starting keyframe for that chunk was distorted in some way but the video container is still applying the changes to the faulty starting point. To quickly cut up a video, ffmpeg can easily split them at the key frames, whereas to have the start and end point not at the keyframes would require additional rendering. -- **Command I often use** To download 720p versions of a video (it's very rare that isn't perfectly adequate) and ensure it's put into an mp4, I use this first command. > yt-dlp -f "bv*[height<=720]+ba/b[height<=720]" "desired_video_url" --merge-output-format mp4 -o "C:\Users\Iris\Desktop\%(title)s.%(ext)s" Then if I only want to keep part of the video, I use this ffmpeg command to make a specific cut and delete the original. > ffmpeg -ss 3238.120 -to 6123.510 -i "path_to_your_local_file" -c copy -avoid_negative_ts make_zero "C:\Users\Iris\Desktop\example_output--cut.mp4" --
